## 精度試験の結果

保存された実行記録の16 engine・31条件はCとSの合計。今回のSは13 engine・26条件で、全て保存された検査で合格。別のSGEMM 8192³の検査では、一様・正規とも20/21bitが不合格、22/23/24/25bitが合格（12条件、うち4不合格）。これらは元入力に対する1,024点の精度検査であり、全入力の正確さや法ごとの恒等式の合否とは混同しない。

K96の記録は18条件。既存の出力検査の合格8条件、合否の値を引用できない記録10条件。うち4条件は実行版との対応が未確認（`k96_s23_gemm`, `k96_s21_gemm`, `k96_s23_syrk_k4096_a`, `k96_s22_gemm_k4096`）。資産一覧に存在するだけの記録を、読み込んで実行した実体の一致へ読み替えない。後者2件では元の公開用の証跡自体が対応を未確認としている。

## 取り込みと再検算

公開用のheaderから、法・面の種類・全LUTを読む。重みはLUTに保存された単位リムの行から確定し、全剰余で照合する。既存の4形式を同じ係数式へ正規化し、runtimeの表の積と面の数を照合する。新しい重み・法の組は求めない。保存実行版はsource manifest、表と元JSON、summary、個別結果、実行バイナリのhashを照合する。SGEMMの結果は保存tarのmemberをsummaryのhashと照合して読む。

```sh
nice -n 10 taskset -c 0 python3 -m tools.check_fp32 data/modular/fp32-history.json
```

全28構成・328,333剰余対、16組のCRTと累積限界を検算（検算器1.0.0、2026-10-15）。従来の正本との重複をIDで除くと、法の構成115→120、保存組85→100。各記録の出所・表・実行出力のSHA-256はJSONに収録。データの読み込みで古い構成の数値を上書きしない。
