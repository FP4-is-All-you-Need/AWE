# 構成と画面のJSON / JSONL

画面の「構成と画面のJSON / JSONL」で、読み込んだ構成の本体、測定項目、費用の仮定、選択状態を保存する。JSONは記録の配列、JSONLは1行1記録。同じ内容をどちらからも読み込める。サーバーへ送信せず、このタブのsessionStorageへ保持する。別のタブやブラウザへはファイルも渡す。

| type | 内容 |
|---|---|
| awe_view | version=1。queryはURL引数の `[名前,値]` の配列。replaceのような重複する名前も保持する |
| construction | valueに構成の記録。選択済みの表を含む。現在読み込んでいる法の構成、穴あり比較、開いた整数構成を出力する |
| retained_row | line、reason、raw。読み取れない/未対応の行を元の内容と一緒に保持し、次の書き出しにも含める |

構成のvalueには `modulus`（整数構成は0）、`weights.A/B`、`planes.A/B`、`products`（a/bは面の0始まりの番号、numeratorは復元係数、groupは累積器番号またはnull）、`denominator`、`shape`、`faces_a/b`、`holes.count/share`（shareは0〜1またはnull）、`carry`、`block_shift` がある。`saved_encoding.A/B`は整数/剰余からリム列への保存表。`encoding_domain`、`hole_values`、`correction`、`max_k`、出典のSHA-256も保持する。追加項目はadditionalに残す。既存の正本schemaを変更する形式ではなく、画面の読み書き用の記録である。

初めに書き出したファイルをひな形にできる。利用者の記録は、法の候補へ加え、読み込んだ構成の選択欄でも詳細を開ける。整数の構成を剰余の構成として自動変換しない。収録済みの記録と同じ物は既存のIDへ合わせ、異なる内容に同じIDを流用しない。新しい内容には内容のSHA-256からIDを付ける。同じ内容の写しを1件にまとめる。

測定値は入力の主張として保持する。係数式の一致/ずれは表示時に計算するが、ファイルの読み込みを厳密な被覆証明の代わりにしない。未知の補正、穴、係数式の不一致を合否で排除しない。未収録のLUTや全表現を生成しない。

1回に8 MB・5,000記録まで。表示器で扱えない次元や記録形式は、理由を付けて別欄に保持する。ブラウザ保存容量を超える場合はエラーを表示する。
