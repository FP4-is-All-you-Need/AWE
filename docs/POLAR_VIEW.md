# Polar and composite-modulus tables

The format control switches the whole page between the exact checked FP4, FP6 E2M3 and FP6 E3M2 collections. The periodic table, modular list, modulo spiral and composite table do not mix FP4 rows into FP6. The current collection has no FP6 counterpart for the saved FP4 integer-width maps or numerical examples; those views are absent on the FP6 page and the data limitation is stated. The saved FP6 (8×E2M3) modulus sets are listed with the other saved sets on the FP4 page.

The composite table is closed by default and follows the rectangular periodic table. It compares a modulus with its coprime prime-power factors. Product minima and cost minima are selected independently. Missing component constructions leave the corresponding sum unknown. Highlighting means that the combined construction uses fewer products than the sum of the recorded component minima. It does not include CRT reconstruction or establish an optimum beyond the published candidates. With holes enabled, the compared constructions can have different hole counts. Pagination defaults to 15 rows; the page-size control and molecule_page_size URL parameter change it.

Selecting a modulus opens a details panel with its component minima, combined product count, planes, limbs, and costs. A second diagram uses the original published planes, products and coefficients to project that same combined construction onto each prime-power component. It marks products, planes and limbs contributing to multiple components. It checks denominator invertibility, the validity of ignoring plane reductions, and the bilinear coefficient identity before drawing component links. Unsupported components remain unconfirmed. The diagram does not identify its encodings with the independently optimal component encodings, and shared product counts are not equated with the savings above.

The modulo spiral assigns a sector to every integer, including moduli without a recorded construction. Default turn r holds 13r integers: the first turn is 2..14, the second 15..40. The first-turn count can be changed to 10, 11 or any integer 2..32. Angular widths and thickness interpolate arithmetically by default; geometric interpolation and the earlier power-boundary layout remain URL options. Sector boundaries join continuously, and each complete turn spans exactly 2*pi. The spiral radius remains r0+b*theta. Colour defaults to ordered product-count bins; tier mode shares the existing replacement-candidate classification. An in-chart one-line legend gives the mapping. Missing constructions have hollow marks, holey ones have hatching, composites have dashed borders, and product-saving composites have stronger borders. Labels remain upright and the centre is blank. The existing detail pane shows the selected modulus; whole-diagram zoom remains independent of selection.

See [URL controls](URL_CONTROLS.md) for names, ranges, defaults, coordinate definitions and an example link.

The six adjustable cost coefficients retain the catalog model's defaults: plane 0.245, encoding operation 0, modulus 0.63, accumulator 0.24, hole correction 77.44, and FP6/FP4 time ratio 3.1. FP4 products have unit cost. The model adds the weighted product, plane, encoding, modulus, accumulator and hole-correction counts. When available, the shift model competes with hole correction. FP32/INT32 accumulation, K, input width and the correction method are selectable. These are illustrative coefficients, not measurements. Encoding counts are estimates, and the FP6 time ratio is provisional. These controls are shared between the tables and are separate from the application's matrix-size cost settings.

For a selected modulus, dominance is evaluated within each checked value set using the ten catalog measures: products, A planes, B planes, encoding operations, pair hole mass, coefficient width, negative safe K, accumulators, products after shifting, and whether shifting is needed. Missing metadata remains unknown and is not filled with zeros. Cost minima only cover candidates with matched cost metadata. Different coefficient choices can change the selected construction.

`data/visualization/polar-catalog.json` is a compact display index. Construction ids and structural values refer to the published modular JSON files named in each row. Duplicate constructions were removed by the catalog's canonical comparison before making this index. Weights, products (`R`) and planes (`FA`, `FB`) count a construction as the site shows it, without the limbs that never reach a product; a construction that then equals another row of its modulus is listed once. `python -m tools.display_indexes build` rewrites these columns from the published files and `check` compares them. The cost-model columns (`model`: accumulator counts, encoding operation counts, hole mass, coefficient width and shift length) were computed for the published record with all its limbs and are not recomputed. Model metadata was attached only when the checked value set, weights, planes, plane moduli, product list, denominator, hole counts and face counts matched. The source catalog and model-index SHA256 values are recorded in the JSON. `inCatalog` restricts the composite table to constructions matched in that catalog by canonical comparison or retained from the additional checked FP6 collection of 2026-10-20. No private source names or search logs are included.

Validation compares the cost and dominance implementation with the existing catalog implementation, checks the source catalog against its published-current manifest, and checks default folding, page-wide value-set isolation, URL round trips, invalid parameter fallbacks, composite filtering, molecule source counts, both languages, narrow screens and a 1920×1080 view. The original periodic and construction-list sections remain available.

The [xy comparison record](XY_COMPARISON.md) describes the seven candidates, their matches in the earlier catalog, and their inclusion or deferral under the unchanged public verifier.

Additional FP6 constructions without matched cost metadata remain explicit; no cost is filled in.
