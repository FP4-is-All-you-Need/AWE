# Polar and composite-modulus tables

The format control at the top selects FP4, FP6 E2M3, or FP6 E3M2. The rectangular periodic table retains FP4 constructions in its FP6 view because those integer values are contained in both FP6 value sets. The polar and composite tables initially show the selected checked value set alone; their optional FP4 comparison uses the same inclusion rule.

The composite table is closed by default and follows the rectangular periodic table. It compares a modulus with its coprime prime-power factors. Product minima and cost minima are selected independently. Missing component constructions leave the corresponding sum unknown. Highlighting means that the combined construction uses fewer products than the sum of the recorded component minima. It does not include CRT reconstruction or establish an optimum beyond the published candidates. With holes enabled, the compared constructions can have different hole counts.

The polar view places integers from 2 through 65,536 on a Sacks or Ulam spiral. Circle, square, and diamond shapes distinguish primes, nontrivial prime powers, and moduli with multiple distinct prime factors. Filled marks are hole-free; outlines have holes. Faint marks mean that no construction meets the current filters in the published data. They are not impossibility statements. A numeric modulus input provides access to points that overlap at this scale.

The six adjustable cost coefficients retain the catalog model's defaults: plane 0.245, encoding operation 0, modulus 0.63, accumulator 0.24, hole correction 77.44, and FP6/FP4 time ratio 3.1. FP4 products have unit cost. The model adds the weighted product, plane, encoding, modulus, accumulator and hole-correction counts. When available, the shift model competes with hole correction. FP32/INT32 accumulation, K, input width and the correction method are selectable. These are illustrative coefficients, not measurements. Encoding counts are estimates, and the FP6 time ratio is provisional. These controls are shared between the two tables and are separate from the application's matrix-size cost settings.

For a selected modulus, dominance is evaluated within each checked value set using the ten catalog measures: products, A planes, B planes, encoding operations, pair hole mass, coefficient width, negative safe K, accumulators, products after shifting, and whether shifting is needed. Missing metadata remains unknown and is not filled with zeros. Cost minima only cover candidates with matched cost metadata. Different coefficient choices can change the selected construction.

`data/visualization/polar-catalog.json` is a compact display index. Construction ids and structural values refer to the published modular JSON files named in each row. Duplicate constructions were removed by the catalog's canonical comparison before making this index. Model metadata was attached only when the checked value set, weights, planes, plane moduli, product list, denominator, hole counts and face counts matched. The source catalog and model-index SHA256 values are recorded in the JSON. `inCatalog` restricts the composite table to constructions also matched in that catalog by canonical comparison. No private source names or search logs are included.

Validation compares the cost and dominance implementation with the existing catalog implementation, checks the source catalog against its published-current manifest, and checks default folding, global format controls, coefficient changes, both layouts and languages, narrow screens and a 1920×1080 view. The original periodic and construction-list sections remain available.

The [xy comparison record](XY_COMPARISON.md) describes the seven candidates, their matches in the earlier catalog, and their inclusion or deferral under the unchanged public verifier.
