# 構成の配色と検査

配色の実装の正本は `site/src/compact.ts`。基底色は `productPalette.ts`。図4と図3の方式の色は別の凡例であり、この割り当ての対象ではない。

|役割|割り当て|文字・背景|
|---|---|---|
|直接積 P、単一セルの T|重みの積の昇順、同値なら B と A の重み順。ピンク・紫・藍・青・シアン・青緑・緑・黄緑・オリーブ。別の項へ同色を再使用しない|塗り30%、白の上。文字は同系色の読める濃さ|
|差の積 M、複数セルの T、和差の面の積|支持セルの中央の位置に近いブロック色を優先し、構成内でまだ使わない色を割り当てる。位置の順で処理し、同位置は行・列・面係数で順を決める|橙、ベージュ、空色、黄緑、はちみつ。ベージュの枠は #A0825E、塗りは #CCAA88。塗り42%、白の上|
|6個目の異なる和差の積|論文の繰り上がりの色 #B25000 を使用|同じ文字・塗りの規則|
|面|その面を最初に使う保存済みの積の色。選択中の積によって変更しない。未使用の面は未使用の基底色|面ごと、片側ごとに重複を検査|
|冪の法の重み（1・p・p²）・ミニ図の重み|A/Bの異なる重みをまとめて昇順にし、基底色を1色ずつ割り当てる。1、p、p²は別色|白に8%の塗り。文字とこの背景で4.5以上。mod 1331の11は以前より明るい紫、121は藍|
|式の項と図の項|同じ保存済みの積番号は同色。別の番号は別色|文字色を暗くする場合も式と図の文字で同じ処理|

9色を超える直接セルには、基底9色のRGB各成分を19ずつ下げた離散的な色を順に使う。従来の「末尾を同じ黒にする」処理を廃止した。現在の全入力で重複がないことを検査する。混色の補間は行わない。

`textInk` は色のRGBを同率で暗くし、背景に対して4.5以上にする。色相を潰して同じ文字色になる「各成分から同じ数を引いて0へ切り詰める」処理は使わない。背景を指定しない文字には、現在の白合成の塗りより暗い #B2B2B2 を検査の下限として使う。文字を含む面全体を半透明にする処理も廃止した。

同じ項の再掲、同じ面への複数の矢印、同じ重みのA/Bの対応、共通の黒い数式記号は重複違反にしない。別の項・別の面の色と、その文字色を検査する。構成を跨ぐ色の再使用は認める。位置・数値・係数・保存順は変更しない。

## 全件検査

`cd site && nice -n 10 taskset -c 0 node --experimental-strip-types scripts/audit-colors.ts ../build/color-audit`

整数正本、法の正本、冪の法、全幅の保存組、比較用構成を読み、同じID・重み・面・積の重複を除く。184,844件の表示定義に対し、式・タイル・候補・展開・面・行列が共有する配色関数の結果を検査する。違反にはID、出所、場所、項、色、背景、比を記録する。全件をブラウザに描画した検査ではない。

結果は `COLOR_AUDIT.json`。変更前4,809,722件（重複1,172,101、コントラスト3,637,621）、変更後0件。重み(9,15,28)の5積の例は35件→0件。変更前には、積の色とは独立した重みの固定紫・黒の洗いも含む。

実際の描画への適用は `color-audit.spec.ts` で英日・式・面・ミニ図を検査し、`block-colors.spec.ts` でタイル・展開・面・候補の対応を検査する。`color-audit.test.ts` は5積と6種類の冪の法、`product-palette.test.ts` は並べ替え前後の対応を検査する。


## 分子の成分の凡例

分子の格子は、既定では成分の法の昇順に基底色を割り当てる。複数の成分に寄与するセルは、寄与する成分の色(白に55%)を幅 6 の帯で交互に並べた 45 度の斜線で塗る。これは積の色とは別の凡例で、成分専用の塗りは30%、白に合成し、文字は textInk を使う(斜線のセルの文字は黒)。成分数が増えれば色も増え、新しい色は足さない。「保存した積」に切り替えた時は productFillColor / coefficientColor をそのまま使い、既存の Expansion と同じ色にする。複数の積はセル内で帯に分け、混色しない。

## 費用の表の素因数

`primeColors.ts` は、主要6素数に色相を離した既存のAWE色を先に割り当てる。2はピンク #C2185B、3は紫 #884499、5はオリーブ #9E9D24、7は青 #0277BD、11は橙 #E8710A、13は緑 #43A047。残りは基底色とその離散的な暗色を重複なく順に使い、それ以降は8刻みのRGB色で補う。65536以下の全6542素数で色を再使用しない。素数の順位は目録・表示条件・FP4/FP6に依存しない。冪は底の素数の色を保ち、指数を添える。合成数は成分ごとに色を分け、混色しない。背景は白に30%を合成し、文字は textInk で4.5以上にする。多数の色だけで判別する必要がないよう、素数の数字を常に残す。これは積・面・分子の格子とは別の凡例。積・面の割り当ては変更しない。

## 極座標の帯

既定の `polar_color=prime` は素数の法だけを、上の「費用の表の素因数」と同じ素数ごとの色で塗る（白に30%、縁はその色、数字は textInk）。素数べきと合成数は黒 #1A1A1A の縁の白で、数字は黒（□で囲まない）、その下に素因数を分子の表と同じ札の色の□で並べる（`polar_factors=exponent` は指数を右上、`repeat` は指数の数だけ同じ□）。成分の和より積が少ない合成数は、減る積の本数だけ数字に下線を引き、区画の黒い縁を太くする(ほかの区画の縁に比べて、1 本減るなら 3.6 倍、2 本なら 5.4 倍)。斜線は黒。積と面の印（`polar_mark`）は黒の太い□・太字・帯の厚み・縁の黒い帯だけを使い、色を足さない。2倍以上の拡大で区画を構成ごとの段に分ける時も、段の境は黒の細い実線、選んだ段は黒の縁と黒 20% の塗り、その行は太字だけで、色を足さない。

`polar_color=products` は積の本数。1、2、3、4、5–6、7–8、9–12、13–16、17以上の順に基底9色を使い、白に30%で合成する。費用や合成数の削減の有無でこの色を薄めない。図内の1行の札は同じ割り当て。`polar_color=tier` は候補欄と共通の constructionTier 関数で、積数最少=ピンク、穴なし=青、穴・補正あり=橙、率未測定=灰色。最少は同じ形式・フィルターの表示中の構成の積の本数と比べ、穴が上限だけの記録は率未測定にする。斜線は穴、紫の破線は合成数、太い破線は成分の和より積が減ることを表す。

素因数の種類数の比較用表示 `polar_factors=dots|bands` は黒い小点または黒い細線だけを重ね、積数/tierの塗り色を変えない。bandsでは種類数の区画に分け、1種類なら内部の線は無い。既定は指数まで見せる exponent。
